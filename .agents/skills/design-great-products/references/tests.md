# Subtraction and readiness tests

Run only the tests that change the call. Cite the test name in the report.

| Test | Failed when | Fix |
| --- | --- | --- |
| And | The job sentence needs "and" | Pick one job. Rest is `later` or `kill` |
| Manual | User needs a prompt guide, slash sheet, model picker, MCP explainer, or settings tour before the job works | Default path finishes the job from a lazy first action |
| Better-horses | The proposal is ChatGPT-for-X, more agents, more settings, or a sidebar around a chat box | Show the finished artifact or completed task |
| Empty-box | Primary surface is an empty field plus send, with no first-move opinion | Arrive with work to accept or reject. Chat is an escape hatch |
| Ten-second | No real draft, answer, or action in ten seconds | Cut theater. Show progress that is the job |
| Glue | User must choose between surfaces, memories, or personalities to finish one job | One job, one memory, one voice |
| Seam | User can see the join between model, tools, permissions, and UI | Hide or own the join. Do not narrate the stack |
| Crease | User must overlook lag, confident wrong actions, or a setup ritual | Do not ship the compromise |
| Unseen | Wrong-answer recovery, undo, empty states, partial tools, or privacy defaults are undesigned | Design the path that is not the screenshot |
| Apology | Shipping still needs "users will learn it", a tooltip, or "the model will get better" | Cut or restart. Do not document the failure as onboarding |

A universal box can pass Empty-box only when a vague first message still produces the right next step.
